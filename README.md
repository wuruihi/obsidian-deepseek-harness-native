# DeepSeek Harness Native（DSH 原生面板）

一个 Obsidian 插件，让你**直接在笔记侧边栏里打开本地 DeepSeek Harness（DSH）面板**，不用切到浏览器。把 DSH 的智能体对话、代码执行、文档检索能力嵌进你的笔记工作流，并自动管理本地 DSH 服务。

> 隐私：本插件只连接你本机的 `127.0.0.1` 上的 DSH 服务，不向任何第三方发送数据。

## 它能做什么

- **侧边栏面板**：在 Obsidian 内打开 DSH 对话界面。
- **双向桥接**：一键把当前笔记内容发给 DSH，结果回写 vault。
- **模型与权限**：底部切换模型（DeepSeek V4 Flash / Pro）与执行权限（queue / steer）。
- **服务自动管理**：启动命令留空即**自动探测本机 DSH**（PATH 上的 `dsh`、`~/dsh`、`~/deepseek-harness` …），打开面板时若本地 DSH 未运行则自动拉起；内置「一键安装」克隆并安装 DSH。
- **历史与会话**：新建 / 切换 / 历史会话，自动渲染 DSH 流式回复（含思考链）。

## 安装方式一：手动放置（推荐，最简单）

适合从网盘/聊天记录拿到压缩包的用户。

1. **下载** 压缩包 `deepseek-harness-native-x.x.x.zip` 并解压，会得到文件夹 `deepseek-harness-native/`。
2. **打开你的 vault 文件夹**（Obsidian 里：打开命令面板 → 输入 `打开 vault 所在文件夹` 并回车）。
3. 进入里面的 `.obsidian/plugins/` 目录（`.obsidian` 是隐藏文件夹，需显示隐藏文件）。
4. 把解压出来的 `deepseek-harness-native/` 整个文件夹**复制进去**，和已有的其他插件并列。
5. **重启 Obsidian**（或命令面板执行 `重新加载应用` / 开发者模式下点插件旁边的刷新按钮）。
6. 打开 **设置 → 第三方插件 → 已安装**，找到 `DeepSeek Harness Native`，点开关启用。
7. 首次启用会弹出 **「是否信任来自互联网的插件」** 提示，点 **「信任作者并启用」** 即可。

> 提示：目录名必须是 `deepseek-harness-native`（和 manifest 里的 id 一致），改名会导致 Obsidian 识别不了。

## 安装方式二：BRAT（可自动更新，可选）

适合愿意用 Beta 插件安装器、希望以后一键升级的用户。

1. 在 Obsidian 社区插件市场安装 **BRAT**。
2. 打开 BRAT 设置 → `Add a beta plugin`。

   ```
   https://github.com/wuruihi/obsidian-deepseek-harness-native
   ```
3. 启用插件（同样需要信任提示）。以后有新版本，在 BRAT 里点 `Check for updates` 即可升级。

## 前置条件

本插件是 DSH 的「界面」，本身不含 DSH 引擎。使用前你需要在本机装好 DSH：

- **推荐：用桌面版 App**（`DeepSeek Harness`）。插件默认「连接的 DSH 实例 = 自动」，会优先附身已经打开的桌面版（`127.0.0.1:19387`），与桌面版/GUI 共享同一批会话；桌面版没打开时会自动帮你打开（可在设置里关）。
- 或手动装旧版 CLI（`dsh web`，默认 `127.0.0.1:3080`）：装好后把插件设置里的「启动命令」**留空**（推荐：自动探测），或填写你自己的启动方式（插件会以 vault 为工作目录启动它），并把「连接的 DSH 实例」切成「旧版 dsh web」。
- 一键安装（**仅对旧版 CLI 形态**）：**设置 → DSH Native → 一键安装**，会自动克隆并安装。

> 连不上时先看插件设置：「连接的 DSH 实例」选**自动**，再点面板上的「诊断 DSH」——诊断会同时列出两个候选实例的探活结果，并直接告诉你下一步该做什么。

## 基本使用

- 命令面板执行 `打开面板` 打开侧边栏面板。
- 在输入框输入问题，回车发送；底部可切换模型与执行模式。
- 选中笔记内容后执行 `发送当前笔记到 DSH`，把笔记发给 DSH 处理。

## 设置项

设置页分三段：**常用**（日常会动的）、**快捷操作**（动作按钮）、**高级**（技术设置，默认收起）。

| 位置 | 项目 | 说明 |
|---|---|---|
| 常用 | DSH 安装状态 | 检查是否装好 DSH；未装可「一键安装」（旧版 CLI 形态） |
| 常用 | **连接的 DSH 实例** | `自动`（默认，优先附身桌面版 App 19387，其次旧版 `dsh web`）/ `桌面版 App` / `旧版 dsh web`（自定义端口） |
| 常用 | 旧版 dsh web 端口 | 只在选「旧版 dsh web」时出现 |
| 常用 | 找不到实例时自动打开桌面版 App | 连不上时自动拉起桌面版（找不到安装位置只提示） |
| 常用 | 现在打开桌面版 App | 手动拉起桌面版；插件不接管它的生命周期（不会重启/杀掉它） |
| 常用 | 自动启动 | 仅「旧版 dsh web」模式：端口无服务时自动运行启动命令 |
| 常用 | 发送模式 | `queue`（追加排队）/ `steer`（打断插队） |
| 常用 | 框选发送按钮 / 发送后自动打开面板 | 两个交互开关 |
| 快捷操作 | 在浏览器打开 DSH / 重启 DSH 服务 / 一键检测并填入 | 动作按钮（重启只对旧版实例生效；桌面版实例只重连/帮忙打开） |
| 高级 | 启动命令 | 留空 = 自动探测本机 DSH 安装（推荐，跨机器可用）；也可手填，`{port}` 自动替换；需以 vault 为 cwd |
| 高级 | Vault 路径 / 安装目标目录 / 启动等待时间 / 进程独立常驻 / 安装地址 / 鉴权 Token | 技术项，通常不用动 |
| 高级 | 插件版本 | 当前加载的 main.js 构建标识（版本号 + 加载时间），排障时对照用 |
